# 线程和进程
## 线程和进程的区别
![[Pasted image 20260519163554.png]]
- 进程:==指计算机中正在执行的一个程序实例。它包括了程序的代码、数据和运行时的状态==。每个进程都有自己独立的内存空间，它们之间不能直接访问对方的内存。==进程之间是相互独立的==，它们在操作系统中被视为独立的个体，可以独立调度和管理。==每个进程都有一个唯一的进程标识符(ProcessIdentifier，PID)用于标识和管理。==
- 线程:是==进程的执行单元==。一个进程可以包含==多个线程，它们共享相同的内存空间和其他资源==。线程是进程内的一个独立执行流，它可以看作是进程的一个子任务。不同的线程可以并发地执行，它们之间可以共享数据和资源，相比于创建多个独立的进程，使用线程可以更有效地利用系统资源。线程之间的切换开销相对较小，因为它们共享了相同的上下文环境。

| 场景 | 进程 | 线程 |
|------|------|------|
| 你同时用微信和浏览器 | 微信是一个进程，浏览器是另一个进程 | 微信里同时发消息、传文件、刷朋友圈是多个线程 |
| 资源占用 | 微信和浏览器各占一块内存，互不影响 | 微信内部多个线程共享同一块微信内存 |
| 崩溃影响 | 微信卡死，浏览器照常运行 | 微信里某个线程卡死，可能导致整个微信闪退 |
## 线程创建的三种方法
1. 继承Thread类，重写Run方法
```
class MyThread extends Thread {
    public void run() {
        // 线程执行逻辑
    }
}

// 创建线程并启动
MyThread thread = new MyThread();
thread.start();
```
2. 实现Runnable接口，重写run方法
```
class MyRunnable implements Runnable {
    public void run() {
        // 线程执行逻辑
    }
}

// 创建线程并启动
MyRunnable runnable = new MyRunnable();
Thread thread = new Thread(runnable);
thread.start();
```
3. 实现Callable重写call方法，配合FutureTask
在Java中，除了使用Runnable接口来创建线程，还可以使用Callable接口来创建线程，一般用于有返回结果的同步非阻塞方法。与Runnable不同的是，Callable可以返回一个结果并抛出一个异常。要使用Callable接口创建线程，需要遵循以下步骤:
1.创建一个实现Callable接口的类，并实现其call()方法。call()方法是Callable接口的唯一方法，它定义了线程的执行逻辑，并可以返回一个结果。
```
import java.util.concurrent.Callable;

class MyCallable implements Callable<Integer> {
    public Integer call() throws Exception {
        // 线程执行逻辑
        // 返回一个结果
        return 42;
    }
}
```
2创建一个ExecutorService线程池来管理线程的执行。可以通过Executors类的静态方法来创建线程池。
```
//创建线程池
ExecutorService executor = Executors.newSingleThreadExecutor();
```
3提交Callable任务给线程池进行执行，并获取Future对象。Future对象用于表示异步计算的结果。
```
// 提交Callable任务并获取Future对象
Future<Integer> future = executor.submit(new MyCallable());
```
4可以通过==Future对象来获取Callable任务的执行结果==。调用Future的get()方法会阻塞当前线程，直到Callable任务完成并返回结果。
```
try{
	//获取任务执行结果
	Integer result = future.get();
	System.out.println("结果:"+ result);
} catch  (Exception e){
	e.printStackTrace();
}
```
5在使用完Callable任务后，需要关闭线程池以释放资源。
```
executor.shutdown();
```
使用Callable接口创建线程可以获取线程执行的结果，并可以捕获异常。它适用于需要返回结果的计算密集型任务或需要处理异常的任务场景。通过线程池管理Callable任务的执行，可以提高线程的效率和资源利用率。注意，==Callable接口和Runnable接口的区别==在于==Callable可以返回结果==和==抛出异常==，但是==Callable任务的执行必须通过ExecutorService线程池来进行调度==。
## 线程生命周期
![[Pasted image 20260519164911.png]]
在Java中，线程可以处于不同的状态，这些状态反映了线程在不同阶段的行为和状态变化。Java中的线程状态可以分为以下几种:
1. 新建(New)状态:当线程对象被创建但还没有调用start()方法时，线程处于新建状态。此时，线程已经被创建但还没有启动执行。
2. 可运行(Runnable)状态:当线程对象调用了start()方法后，线程进入可运行状态。在可运行状态下，线程已经==具备了运行的条件==，但并不一定正在执行，==可能正在等待CPU的调度==。
3. 运行(Running)状态:在可运行状态下，==线程被CPU调度执行时，线程进入运行状态==。在运行状态下，线程正在执行其任务代码。
4. 阻塞(Blocked)状态:在某些情况下，线程可能会被阻塞。例如，线程在等待获取锁、等待输入输出完成、等待其他线程的通知等情况下，线程会进入阻塞状态。在阻塞状态下，线程暂时停止执行，直到满足了阻塞条件才能继续执行。
5. 等待(Waiting)状态:线程可以通过调用Object类的wait()、Thread类的join(、LockSupport类的park()等方法进入等待状态。在等待状态下，线程暂时停止执行，并释放占有的锁，直到其他线程发出通知或等待时间到达。
6. 超时等待(Timed Waiting)状态:类似于等待状态，线程通过调用具有==超时参数==的wait()、join()、sleep()等方法，进入超时等待状态。在超时等待状态下，线程暂时停止执行，直到其他线程发出通知、等待时间到达或超时时间到达。(==只是加了个超时参数，超过该时间自动解除等待状态==)
7. 终止(Terminated)状态:线程执行完其任务代码或出现了未捕获的异常时，线程进入终止状态。在终止状态下，线程的执行已经结束，不再具备执行的条件。
阻塞和等待区别
- 阻塞是指线程由于外部条件（如等待 I/O 操作、获取资源等）无法继续执行，线程会被挂起，直到外部条件满足。
- 等待是指线程主动进入等待状态，通常是因为它在等待其他线程的通知或某个条件的变化。
这两个概念的关键区别在于 ==谁控制线程的暂停==：阻塞通常是由==外部事件（如 I/O 操作）控制==的，而等待是由==线程自身决定并等待其他线程的唤醒==。
# 锁
## JAVA中锁的分类
#### 可重入锁、不可重入锁
![[AIEnhancer_331f288569dd205d30af43faacf7d0.png]]
```
class A{

    synchronized void fun(){
        synchronized(A.class){
            //...
        }
    }

    void main(){
        A objA = new A();
        synchronized(objA){
            //...
            //...
            //...
            //...
        }
    }
}
```
- 可重入锁一避免死锁
Java中提供的==synchronized、ReentrantLock、ReentrantReadWriteLock==都是可重入锁。可重入锁是指同一个线程在持有锁的情况下，可以重复地获取同一个锁，而不会造成死锁或其他异常情况。当一个线程多次获取同一个可重入锁时，必须相应地释放相同数量的锁，才能完全释放该锁。可重入锁的主要特点是:
a.同一个线程可以多次获取同一个锁。
b.线程在释放锁之前必须相应地释放相同数量的锁。
c.可重入锁可以避免死锁和其他异常情况。
==**可重入锁 = 锁里还能套同一把锁，自己不会把自己锁死，但进去几次就得出来几次。**==
- 不可重入锁:
不可重入锁是指同一个线程在持有锁的情况下，再次尝试获取该锁时会导致线程被==阻塞或产生死锁==。不可重入锁不允许同一个线程重复获取同一个锁，即使是在同一个线程的内部。不可重入锁的主要特点是:
a.同一个线程无法多次获取同一个锁，会导致线程被阻塞或死锁。
b.不可重入锁可能会导致死锁和其他异常情况。
==**不可重入锁 = 锁里不能再套同一把锁，一旦套了，自己把自己锁死。**==
#### 乐观锁、悲观锁
1. 悲观锁 (Pessimistic Locking):
悲观锁==假设在整个操作过程中会发生并发冲突，因此在访问共享资源之前会将其加锁，阻止其他线程对该资源的访问，直到当前线程完成操作并释放锁==。悲观锁常见的实现方式是使用互斥锁(如synchronized关键字或ReentrantLock类)来保证对共享资源的独占访问，确保数据的一致性。Java中提供的==synchronized.ReentrantLock、ReentrantReadWriteLock==都是悲观锁，获取不到锁资源的时候，会将当前线程挂起(进入BLOCKED，WAITING)，线程挂起会涉及到用户态和内核态的切换，这种切换是非常消耗资源的。
2. 乐观锁 (Optimistic Locking)
乐观锁==假设在整个操作过程中不会发生并发冲突，因此不会使用锁来保护共享资源的访问==。相反，它通过使用一种乐观的策略来进行操作，通常是使用无锁的并发控制机制(如CAS操作)。乐观锁的思想是，在读取共享资源时不进行加锁，而是先读取资源的版本号或标记，然后在更新资源时比较版本号，如果发现其他线程已经修改了资源则放弃当前操作，重新尝试或执行相应的冲突解决策略。Java中提供的CAS操作就是一种乐观锁，当获取不到锁资源的时候，可以再次让CPU调度，重新尝试获取锁资源。
乐观锁和悲观锁的选择取决于具体的场景和需求:
- ==悲观锁适用于对共享资源的并发访问较为频繁，且冲突较多的情况==。它能够保证数据的一致性，但可能会导致线程的阻塞和上下文切换，对系统的并发性能有一定的影响。
- ==乐观锁适用于对共享资源的并发访问冲突较少的情况==。它通过避免加锁操作来提高并发性能，但需要实现冲突检测和冲突解决策略，确保数据的一致性。
在Java中，==乐观锁的常见实现方式是使用CAS(Compare and Swap)操作==，例如使用Atomic类或StampedLock类。而==悲观锁则可以通过synchronized关键字或ReentrantLock类来实现==。选择合适的锁策略取决于对数据一致性和并发性能的权衡。
#### 公平锁、非公平锁
![[Pasted image 20260527000233.png]]
在Java中，公平锁(Fair Lock)和非公平锁(Nonfair Lock)是锁机制的两种实现方式，用于控制多个线程对共享资源的访问顺序。
Java中synchronized只能是非公平锁，而ReentrantLock、ReentrantReadWriteLock可以实现公平锁和公平锁
1. 公平锁
==公平锁是指多个线程按照请求的顺序依次获取锁。==当一个线程释放锁后，等待时间最长的线程将有机会获取锁。公平锁可以保证线程获取锁的顺序符合其请求的顺序，避免线程饥饿的情况发生。在公平锁中，线程会排队等待获取锁。
魏子点
在Java中，通过ReentrantLock类的构造函数可以创建一个公平锁，如下所示:
```
ReentrantLock lock = new ReentrantLock(true);//公平锁
```
2. 非公平锁
==非公平锁是指多个线程获取锁的顺序不受其请求顺序的限制。==当一个线程释放锁后，任何一个等待获取锁的线程都有机会立即获取到锁，不考虑等待时间的长短。非公平锁可能导致某些线程长时间等待，造成线程饥饿的情况。
在Java中，默认情况下，使用ReentrantLock类创建的锁是非公平锁，如下所示:
```
ReentrantLock lock = new ReentrantLock();// 非公平锁
```
公平锁和非公平锁的选择取决于具体的应用场景和需求:
- 公平锁能够保证线程获取锁的顺序按照其请求的顺序，避免线程饥饿，但可能会牺牲一些并发性能。
- 非公平锁能够提高并发性能，因为等待时间较短的线程有机会更快地获取到锁，但可能会导致某些线程长时间等待，出现线程饥饿的情况。
需要注意的是，公平锁和非公平锁的选择并不一定会影响锁的功能和线程安全性，只是决定了线程获取锁的顺序。
根据具体的场景和性能要求，选择合适的锁类型以优化并发性能或保证公平性。
#### 互斥锁、共享锁
![[Pasted image 20260527000958.png]]
互斥锁(Mutex Lock)和共享锁(Shared Lock)是两种并发编程中的锁机制，用于控制对共享资源的访问。
1. 互斥锁:
互斥锁是一种独占锁，它确保在任何给定的时刻==只有一个线程可以持有锁并访问共享资源==。当一个线程获取了互斥锁后，其他线程必须等待，直到持有锁的线程释放锁才能获取该锁。互斥锁用于保护临界区，防止多个线程同时访问和修改共享资源，以确保数据的一致性和线程安全。在Java中，synchronized关键字和ReentrantLock类都可以用于实现互斥锁。
2. 共享锁:
共享锁是一种==允许多个线程同时持有锁并访问共享资源的锁==。与互斥锁不同，共享锁可以实现多线程对共享资源的并发读取，提高并发性能。多个线程可以同时持有共享锁，只要它们不试图修改共享资源。只有当一个线程持有共享锁时，其他线程才能获取该锁，但它们只能以共享模式读取共享资源。
在Java中，ReentrantReadWriteLock类提供了对共享锁的支持，其中的读锁是共享锁，写锁是互斥锁。读锁可以被多个线程同时持有，写锁是独占的，只能被一个线程持有。互斥锁和共享锁的选择取决于对共享资源的访问模式和需求:
- 互斥锁==适用于对共享资源的修改和独占访问==，保证数据的一致性和线程安全。
- 共享锁==适用于对共享资源的并发读取==，允许多个线程同时持有锁并读取共享资源，提高并发性能。
需要根据具体的场景和需求选择适当的锁类型，以实现对共享资源的正确访问和控制。
#### 分段锁
![[Pasted image 20260527001228.png]]
分段锁(Segmented Locking)是一种在多线程环境中提高并发性能的技术。它通过将数据结构==分成多个独立的部分(段)，并在每个部分上使用独立的锁来减少锁的竞争==，从而==提高并发访问的效率==。分段锁的思想是将一个大的锁分解成多个小的锁，这样可以==允许多个线程同时访问不同的段，而不是阻塞所有线程。==
在Java中，concurrentHashMap是一个典型的使用分段锁的数据结构。在JDK7及之前版本中，ConcurrentHashMap 使用了分段锁来提高并发性能。从JDK 8开始，ConcurrentHashMap使用了更先进的CAS和锁膨胀技术，但分段锁的思想仍然值得学习。
#### 偏向锁、轻量级锁、重量级锁——synchronized
在Java的并发编程中，锁的实现经历了从重量级锁到轻量级锁再到偏向锁的演进，这些锁机制旨在提高多线程环境下的性能和效率。下面详细介绍这三种锁的特性和工作原理。
重量级锁
##### a.重量级锁(Heavyweight Lock)
重量级锁是最传统的锁机制，通常指的是synchronized 关键字。在早期的Java版本中，synchronized 是一个重量级的锁，因为它涉及到操作系统级别的线程调度和上下文切换，这会导致较大的性能开销。特点:
- 互斥性:确保同一时刻只有一个线程可以访问被保护的资源。
- 可见性:确保线程对共享变量的修改对其他线程可见。
- 性能开销:==涉及操作系统级别的线程调度和上下文切换，性能开销较大。==
##### b.轻量级锁(Lightweight Lock)
轻量级锁是在Java6中引入的一种优化机制，目的是减少重量级锁的性能开销。==轻量级锁通过使用CAS操作和自旋锁==来实现。特点如下:
- CAS操作:在进入和退出同步块时，使用CAS操作来尝试获取锁。
- 自旋锁:如果线程获取锁失败，它不会立即进入阻塞状态，而是进入自旋状态，即在一个循环中不断尝试获取锁，直到成功为止。
- 性能提升:在竞争不激烈的情况下，==轻量级锁可以显著减少上下文切换的开销，提高性能==。
工作原理
1. 锁标志位:对象头中包含一个锁标志位，用于标识锁的状态(无锁、轻量级锁、重量级锁)。
2. CAS获取锁:线程尝试通过CAS操作将对象头的锁标志位从无锁状态改为轻量级锁状态。
3. 自旋等待:如果CAS操作失败，线程进入自旋状态，不断尝试获取锁。
4. ==升级为重量级锁:如果自旋次数达到一定阈值或自旋时间过长，轻量级锁会升级为重量级锁。==
##### c.偏向锁(Biased Locking)
偏向锁是Java6中引入的一种进一步优化的锁机制，旨在减少无竞争情况下的锁开销。==偏向锁假设在大多数情况下，锁不会被多个线程竞争，因此将锁偏向于第一个获取锁的线程==。工作原理
1. 初始状态:对象头的锁标志位处于无锁状态。
2. 偏向锁获取:第一个线程尝试获取锁时，通过CAS操作将对象头的锁标志位改为偏向锁状态，并记录线程ID.
3. 后续获取:如果同一个线程再次获取锁，直接检查对象头的线程ID是否匹配，匹配则成功获取锁。子
4. 撤销偏斜:如果其他线程尝试获取已经被偏向的锁，会触发偏向锁的撤销。撤销过程中，锁会升级为轻量级锁或重量级锁。
##### d.锁的升级过程
==锁的升级过程是从偏向锁到轻量级锁再到重量级锁==，这个过程是不可逆的。具体步骤如下:
1. 无锁状态:对象头的锁标志位表示无锁状态。
2. 偏向锁:第一个线程获取锁时，锁变为偏向锁状态。
3. 轻量级锁:如果有其他线程尝试获取锁，偏向锁撤销，锁升级为轻量级锁。
4. 重量级锁:如果轻量级锁的自旋次数达到阈值或自旋时间过长，锁升级为重量级锁。
#### 自旋锁
自旋锁(Spin Lock)是一种在多线程环境中用于实现同步的机制。与传统的阻塞锁不同，自旋锁在尝试获取锁==失败时不会立即将线程阻塞，而是让线程在一个循环中不断尝试获取锁==，直到成功为止。这种机制在某些情况下可以显著提高性能，尤其是在锁竞争不激烈且持有锁的时间较短的场景下。
##### 自旋锁的工作原理
1. 尝试获取锁:线程尝试通过CAS操作获取锁。
2. 自旋等待:如果获取锁失败，线程进入一个循环(自旋)，不断尝试获取锁。
3. 获取锁成功:如果在自旋过程中成功获取锁，线程继续执行。
4. 超时或放弃:如果自旋次数达到一定阈值或自旋时间过长，线程可能会放弃自旋，转而使用阻塞锁。
##### 优点
1. 低延迟:在锁竞争不激烈的情况下，自旋锁可以减少线程上下文切换的开销，提高响应速度。
2. 简单高效:实现相对简单，适用于短时间持有锁的场景。
##### 缺点
1. CPU占用:如果锁竞争激烈或持有锁的时间较长，自旋锁会导致CPU占用率增高，浪费资源。
2. 不适合长时间持有锁:如果线程长时间持有锁，其他线程会一直自旋，消耗大量CPU资源。
3. 不适合高负载系统:在高负载系统中，自旋锁可能导致CPU资源紧张，影响整体性能。
在Java中，自旋锁通常与轻量级锁结合使用，特别是在synchronized 关键字的实现中。从Java 6开始，synchronized 关键字引|入了自旋锁机制，以提高性能。
# 说说synchronized
synchronized 是Java中用于控制多线程访问共享资源的一种同步机制。它可以==通过关键字的形式应用于方法或代码块==，==确保同一时刻只有一个线程能够执行被synchronized修饰的方法或代码块。==通常的使用方式包括修饰同步方法和修饰同步代码块，如下图:
![[Pasted image 20260527161226.png]]
## 1.互斥性
当一个线程进入由synchronized 保护的方法或代码块时，其他试图进入同一个方法或代码块的线程会被阻塞，直到第一个线程退出该方法或代码块。这种机制确保了在同一时刻只有一个线程可以访问被保护的资源，从而避免了数据竞争和不一致的状态。
## 2.可见性
synchronized 不仅提供了互斥性，还保证了内存可见性。即，当一个线程释放了一个synchronized 锁后，所有它对共享变量的修改都会被刷新到主内存中，这样其他线程在获取锁时可以看到最新的值。
## 3.可重入性
如果一个线程已经持有了某个对象的锁，它可以再次进入由该对象锁保护的代码块，而不会被自己阻塞。这种特性称为可重入性。可重入性避免了死锁的发生，因为线程不会因为等待自己已经持有的锁而陷入死锁。
# 说说ReentrantLock
ReentrantLock 是Java并发包(java.util.concurrent.locks)中提供的一个==可重入==的==互斥锁==。与synchronized 关键字相比，ReentrantLock 提供了更多的功能和灵活性，使其在某些场景下更加适用。以下是一些关于ReentrantLock 的关键特性和用法:
## 1.可重入性:
ReentrantLock具有可重入性，这意味着如果一个线程已经持有了某个锁，它可以再次获取该锁而不会被自己阻塞。
这种特性避免了死锁的发生，因为线程不会因为等待自己已经持有的锁而陷入死锁。
## 2.公平性:
ReentrantLock 支持公平和非公平两种模式。
公平锁:按照请求锁的顺序来分配锁，先请求的线程先获得锁。
非公平锁:允许插队，新请求的线程可能会抢占已经等待的线程，从而更快地获取锁。
默认情况下，ReentrantLock是非公平的，但可以通过构造函数指定为公平锁。
## 3.锁的中断:
ReentrantLock支持锁的中断，即线程在等待获取锁的过程中可以被中断。
这在处理长时间等待的线程时非常有用，可以避免线程无限期地等待。
## 4.锁的超时:
ReentrantLock 提供了 tryLock(long timeout,TimeUnit unit) 方法,允许线程在指定的时间内尝试获取锁。如果在指定时间内未能获取到锁，线程将放弃并继续执行其他任务。
## 5.条件变量:
ReentrantLock 提供了 condition 对象,类似于 synchronized 中的 wait()和 notify() 方法。
通过newCondition()方法可以创建一个与锁绑定的条件变量，从而实现更复杂的同步逻辑。

==synchronized是关键字，ReentrantLock是类。==ReentrantLock 提供了比synchronized 更丰富的功能和更高的灵活性，特别是在==需要更细粒度的锁控制、公平性、中断和超时等场景下==[细粒度 = 一把大锁拆 N 把小锁，缩小竞争范围，提升并发度；]。虽然ReentrantLock的使用相对复杂一些，但其强大的功能使其成为处理复杂并发问题的重要工具。
# 什么是CAS
![[Pasted image 20260527164524.png]]
CAS(Compare-and-Swap，比较并交换)是一种==无锁算法==，用于在==多线程环境中实现原子操作==。CAS操作包含三个操作数:==内存位置(V)、预期值(A)和新值(B)==.CAS操作的执行过程如下:
1. 比较:将内存位置V的值与预期值A进行比较。
2. 交换:如果V的值等于A，则将V的值设置为新值B，并返回true。
3. 失败:如果V的值不等于A，则不进行任何操作，并返回false。
CAS操作是原子的，即在单个处理器指令周期内完成，不会被其他线程中断。这使得CAS成为一种高效的同步机制，尤其适用于高并发场景。
## (1)CAS的优点
1.无锁:CAS操作不需要获取和释放锁，因此==避免了锁带来的开销==。
2.高效:在多核处理器上，CAS操作可以充分利用硬件的并行性，==提高并发性能==。
3.避免死锁:由于没有锁的概念，因此==不会发生死锁==。
## (2)CAS的缺点
1.ABA问题:如果一个值从A变为B，再变回A，CAS操作会误认为值没有变化，从而导致错误的结果。为了解决这个问题，Java并发包中引入了AtomicstampedReference类，通过引入版本号来解决ABA问题
2.==循环时间长开销大==:在高竞争的情况下，CAS操作可能需要多次尝试才能成功，这会导致CPU循环等待，增加开销。
3.只适用于简单操作:CAS==适用于简单的原子操作==，对于复杂的同步逻辑，使用锁可能更合适。
## (3)Java中的CAS
在Java中，java.util.concurrent.atomic 包提供了一系列基于CAS的原子类，这些类可以用于实现高效的并发操作。常见的原子类包括:
AtomicInteger:提供原子的整数操作。
AtomicLong:提供原子的长整数操作。
AtomicBoolean:提供原子的布尔值操作。
AtomicReference:提供原子的引用类型操作。
AtomicstampedReference:提供带有版本号的原子引用类型操作，用于解决ABA问题。
AtomicIntegerFieldupdater:提供对指定类的指定 volatile int 字段的原子更新操作。
AtomicLongFieldupdater:提供对指定类的指定 volatile long字段的原子更新操作。
AtomicReferenceFieldupdater:提供对指定类的指定 volatile 引用字段的原子更新操作。
# 什么是死锁
![[Pasted image 20260528000553.png]]==多个进程(或线程)竞争资源==时，==互相等待对方释放自己需要的资源==，导致==所有进程都无法继续执行==，陷入“僵持”状态，这种情况就是死锁。
## (1)死锁的4个必要条件
1. ==互斥条件==:资源只能被一个进程占用(比如打印机、单个文件锁，不能同时给多个进程用);
2. ==请求与保持条件==:进程已经持有部分资源，又要申请新资源，且不释放已持有的资源;
3. ==不可剥夺条件==:其他进程不能强行夺走一个进程已持有的资源(比如进程A占着打印机，进程B不能直接抢)
4. ==循环等待条件==:多个进程形成"你等我、我等你”的循环链(比如进程A等进程B的资源，进程B等进程A的资源)。
## (2)简单例子
- 进程1持有打印机，想申请扫描仪;
- 进程2持有扫描仪，想申请打印机;
- 两者都不释放自己的资源，互相等待，陷入死锁，都无法继续执行打印/扫描任务。
## 核心结论(刷题用)
只要==破坏4个必要条件中的任意一个==，就能避免死锁;
实际系统中常见解决方案:==银行家算法(避免死锁)==、==资源有序分配(破坏循环等待)==、==剥夺资源(破坏不可剥夺)==等。
# 线程池
## 什么是线程池
线程池是一种多线程处理形式，处理过程中将任务添加到队列，然后在创建线程后自动启动这些任务。线程池==管理一组预先创建的、可重用的线程==，这些线程可以在需要时执行提交的任务。线程池的==主要目的是减少创建和销毁线程的开销==，提高响应速度和系统资源的利用率。
### 线程池的工作原理
1. ==任务提交==:当应用程序需要执行一个任务时，它将任务提交给线程池，而不是直接创建新的线程。
2. ==任务队列==:线程池维护一个任务队列，用于存储待处理的任务。任务队列可以是有界的或无界的，具体取决于线程池的配置。
3. ==线程管理==:线程池管理一组工作线程，这些线程不断地从任务队列中取出任务并执行。
4. ==任务执行==:工作线程从任务队列中取出任务并执行。如果所有线程都在忙，新提交的任务将被放入任务队列中等待。
5. ==线程复用==:当一个任务执行完毕后，工作线程会返回线程池，等待下一个任务，而不是被销毁。这样可以避免频繁创建和销毁线程的开销。
### 线程池的优点
1. ==减少资源消耗==:通过重复利用已创建的线程，减少了线程创建和销毁的开销。
2. ==提高响应速度==:任务可以立即执行，而不需要等待线程创建。
3. ==提高系统稳定性==:通过限制系统中活动线程的数量，防止因大量线程同时运行而导致系统资源耗尽。
4. ==更好的资源管理==:可以更好地控制线程的生命周期，例如设置最大线程数、线程空闲时间等。
## 为什么需要线程池
线程池在多线程编程中扮演着重要的角色，它的主要目的是==提高系统的性能和资源利用率==。以下是使用线程池的几个关键原因:
1. ==减少线程创建和销毁的开销==
- 线程创建开销:每次创建和销毁线程都会消耗一定的系统资源，包括CPU时间和内存。频繁的线程创建和销毁会导致系统性能下降。
- 线程池复用:线程池通过复用已存在的线程来执行新任务，避免了频繁创建和销毁线程的开销，从而提高了系统的响应速度和整体性能。
2. ==控制系统资源==
- 限制线程数量:线程池可以限制系统中活动线程的数量，防止因大量线程同时运行而导致系统资源耗尽。这有助于提高系统的稳定性和响应能力。
- 资源管理:通过配置线程池的参数(如核心线程数、最大线程数、线程空闲时间等)，可以更好地管理系统的资源，确保系统在高负载下仍能正常运行。
1. ==提高响应速度==
- 任务立即执行:当任务提交到线程池时，如果有可用的线程，任务可以立即执行，而不需要等待线程创建。这大大提高了任务的响应速度。
- 异步执行:线程池支持异步任务执行，可以将长时间运行的任务放到后台执行，而不阻塞主线程，提高系统的交互性和用户体验。
## Java创建线程池的核心参数?
![[Pasted image 20260528002412.png]]
在Java中，java.util.concurrent.ThreadPoolExecutor 类提供了创建线程池的灵活性，允许开发者根据具体需求配置线程池的各种参数。以下是创建线程池时的核心参数表格

| 参数名称                        | 描述                                           | 作用                                     | 常见类型/值                                                                                                                                                                        |
| --------------------------- | -------------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 核心线程数<br>(corePoolSize)     | 线程池中保持的最小线程数，即使==这些线程处于空闲状态也不会被销毁。==         | 确保线程池中始终有足够数量的线程来处理任务，提高响应速度。          | 例如：5                                                                                                                                                                          |
| 最大线程数<br>(maximumPoolSize)  | 线程池中允许的最大线程数。                                | 限制系统中活动线程的数量，==防止因大量线程同时运行而导致系统资源耗尽==。 | 例如：10                                                                                                                                                                         |
| 空闲线程存活时间<br>(keepAliveTime) | 当线程池中的线程数超过核心线程数时，==多余的空闲线程在等待新任务时的最长等待时间==。 | 控制线程池的资源占用，==减少不必要的线程开销==。             | 例如：60秒，单位通过 `TimeUnit` 参数指定，如 `TimeUnit.SECONDS`                                                                                                                              |
| 工作队列<br>(workQueue)         | 用于保存等待执行的任务的队列。                              | ==管理任务的排队和调度==，影响线程池的吞吐量和响应时间。         | `ArrayBlockingQueue`：有界队列，固定大小的数组实现。<br>`LinkedBlockingQueue`：无界队列，基于链表实现。<br>`SynchronousQueue`：不存储元素的队列，每个插入操作必须等待一个对应的移除操作。<br>`PriorityBlockingQueue`：支持优先级排序的无界队列。       |
| 拒绝策略<br>(handler)           | 当==线程池和工作队列都已满时==，如何处理新提交的任务。                | 控制任务的处理方式，确==保系统在高负载下仍能正常运行。==         | `AbortPolicy`：默认策略，抛出 `RejectedExecutionException` 异常。<br>`CallerRunsPolicy`：由调用线程（提交任务的线程）执行该任务。<br>`DiscardPolicy`：直接丢弃任务。<br>`DiscardOldestPolicy`：丢弃队列中最老的任务，然后重新尝试提交新任务。 |
以下是一个使用ThreadPoolExecutor创建线程池的示例，展示了如何配置上述核心参数:
```
import java.util.concurrent.*;

public class ThreadPoolExecutorExample {
    public static void main(String[] args) {
        // 创建线程池
        ThreadPoolExecutor executorService = new ThreadPoolExecutor(
            5, // corePoolSize
            10, // maximumPoolSize
            60, // keepAliveTime
            TimeUnit.SECONDS, // time unit for keepAliveTime
            new LinkedBlockingQueue<>(100), // workQueue
            Executors.defaultThreadFactory(), // threadFactory
            new ThreadPoolExecutor.CallerRunsPolicy() // handler
        );

        // 提交15个任务
        for (int i = 0; i < 15; i++) {
            int taskId = i;
            executorService.submit(() -> {
                System.out.println("Task " + taskId + " is running by " + Thread.currentThread().getName());
                try {
                    Thread.sleep(1000); // 模拟任务执行时间
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            });
        }

        // 关闭线程池
        executorService.shutdown();
    }
}
```
- corePoolsize:5，表示线程池中始终保持5个核心线程。
- maximumPoolsize:10，表示线程池中最多可以有10个线程。
- keepAliveTime:60秒，表示空闲线程的存活时间。
- workQueue:new LinkedBlockingQueue<>(100)，表示使用容量为100的有界队列。
- threadFactory :Executors.defaultThreadFactory()，使用默认的线程工厂。
- handler:new ThreadPoolExecutor.CallerRunsPolicy()，表示当线程池和工作队列都已满时，由调用线程执行该任务。
## Java中线程池分类

在Java中，java.util.concurrent包提供了多种类型的线程池，每种线程池都有其特定的用途和适用场景。以下是常见的线程池类型及其特点:
### (1)固定线程池(newFixedThreadPool)
- 概述:创建一个固定大小的线程池。一旦达到线程池的最大大小，新任务将在队列中等待，直到有线程可用。

- 概述:创建一个支持定时和周期性任务执行的线程池。
- 特点:
支持定时任务:可以安排任务在==指定的延迟后执行==，或者==定期执行==。
适合定时任务:==适用于需要定期执行任务的场景==。
- 示例代码:
```
import java.util.concurrent.Executors;
import java.util.concurrent.ScheduledExecutorService;
import java.util.concurrent.TimeUnit;

public class ScheduledThreadPoolExample {
    public static void main(String[] args) {
        // 创建一个支持定时任务的线程池，这个5表示线程池的核心线程数（corePoolSize）
        ScheduledExecutorService executorService = Executors.newScheduledThreadPool(5);

        // 提交一个延迟执行的任务
        executorService.schedule(() -> {
            System.out.println("Delayed task is running by " + Thread.currentThread().getName());
        }, 5, TimeUnit.SECONDS);

        // 提交一个周期性执行的任务
        executorService.scheduleAtFixedRate(() -> {
            System.out.println("Periodic task is running by " + Thread.currentThread().getName());
        }, 0, 2, TimeUnit.SECONDS);

        // 为了防止程序立即退出，让主线程睡眠一段时间
        try {
            Thread.sleep(10000);
        } catch (InterruptedException e) {
            e.printStackTrace();
        }

        // 关闭线程池
        executorService.shutdown();
    }
}
```
### (5)自定义线程池(ThreadPoolExecutor)
- 概述:通过ThreadPoolExecutor类创建自定义的线程池，可以灵活配置线程池的各种参数。
- 特点:
==高度可配置==:可以配置核心线程数、最大线程数、空闲线程存活时间、工作队列、线程工厂和拒绝策略。
==适合复杂场景:适用于需要精细控制线程池行为的场景。==
- 示例代码
```
import java.util.concurrent.*;

public class CustomThreadPoolExample {
    public static void main(String[] args) {
        // 创建自定义线程池
        ThreadPoolExecutor executorService = new ThreadPoolExecutor(
            5, // corePoolSize
            10, // maximumPoolSize
            60, // keepAliveTime
            TimeUnit.SECONDS, // time unit for keepAliveTime
            new LinkedBlockingQueue<>(100), // workQueue
            Executors.defaultThreadFactory(), // threadFactory
            new ThreadPoolExecutor.CallerRunsPolicy() // handler
        );

        // 提交15个任务
        for (int i = 0; i < 15; i++) {
            int taskId = i;
            executorService.submit(() -> {
                System.out.println("Task " + taskId + " is running by " + Thread.currentThread().getName());
                try {
                    Thread.sleep(1000); // 模拟任务执行时间
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            });
        }

        // 关闭线程池
        executorService.shutdown();
    }
}
```
Java提供了多种类型的线程池，每种线程池都有其特定的用途和适用场景。选择合适的线程池类型可以提高系统的性能和资源利用率。通过合理配置线程池的参数，可以满足不同应用的需求。
